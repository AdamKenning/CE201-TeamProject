# User Stories

## Explanation and examples

- ### User Story Structure
  - User stories are often expressed in a simple sentence, following a simple structure.
    - “As a **persona**, I **want to**, **so that**.”
  - Explanation of Parts
    - As a **persona**: Defines the user role, like "parent" or "caregiver."
    - I **want to**: Specifies the action or feature the user needs to use.
    - **So that**: Explains the purpose or value this feature provides.
  - This structure ensures that each user story aligns with the software’s goal of supporting child health management 
      and providing actionable insights to users.
  - Source : https://www.atlassian.com/agile/project-management/user-stories

- ### Examples:
---
- As a **parent**, I want to **track my child’s feeding and sleep patterns**, so that I can **establish a 
    healthy routine**.
   - Feeding and Sleep Logs
     - Daily logs for feeding and sleep times, with simple data entry
   - Daily Patterns & Summaries
     - Display a daily or weekly summary of patterns and trends.
   - Feeding Insights
     - Compare feeding patterns with a typical child of similar characteristics (age, height, etc.)
   - Data Accuracy
     - Allow edits to entries to correct mistakes
   - Filling in missed days
     - Provide option to fill in obvious missed entries, with reminder that data may be incomplete
---
- As a **parent**, I want to **receive insights and alerts on my child’s routines**, so that I can see changes in their routine
   - Alerts
     - Notify parents about significant changes in trends or reminders for feeding/sleeping times
   - Projections
     - Show future projections of feeding and sleep patterns to help plan routines
   - Feeding Goals
     - Set and track goals to ensure a balanced diet
   - Notifications
     - Limit notifications to actionable insights, reducing notification overload
   - Privacy and Security
     - Secure storage of personal data, accessible only to the user
---
- As a **caregiver**, I want to **record diaper changes**, so that I can **monitor the child’s digestive health**.
   - Simple Tracking Interface
     - Allow for different types e.g. (peepee, poopoo, etc.)
     - Simple data entry with minimal typing
   - Daily Patterns & Summaries
     - Show a daily / weekly summary of trends
   - Alerts
     - Show alerts based of changes in trends ? more / less often (indicator of health)
   - Projection
     - Show future projections of trends
   - Health Insights
     - Offer potential reasons for changes in diaper patterns (e.g., dehydration or digestive problems)
   - Permissions
     - Allow shared access with multiple caregivers for shared tracking ? (e.g. mom, dad, nanny etc)}
---
- As a **healthcare provider**, I want **access to growth metrics**, so that I can **assess if a child is 
   developing** normally.
   - Graphical Analysis
     - Provide a visual graph showing weight, height etc over time.
   - Standards comparison
     - Provide standard metrics for a child of the same age / height / sex as the one in question
   - Data Export Options
     - Include easy export options (e.g., PDF or CSV) for printing}
---
- As a **caregiver**, I want to **generate daily health reports in PDF format**, so that I can **provide updated 
   information during healthcare visits**.
   - Report Generation
     - Simple one-click generate daily / weekly etc reports summarizing all tracked activities (feeding, sleep, 
       diaper changes)
   - Custom Data Fields
     - Allow the user to choose what is included in the report (e.g. if you only care about pee pee poo poo and 
       not honk mi mi mi )
   - Graphical stuff
     - Include graphs of trends for quick review
   - Data privacy
     - Store historic reports for comparison (e.g. last month vs this month) securely
